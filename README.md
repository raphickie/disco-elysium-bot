# Disco Elysium Telegram Bot

Telegram-бот на TypeScript + Cloudflare Workers + D1 + OpenAI. Оригинальные короткие комментарии голосами навыков Disco Elysium. Требования: [SPEC.md](SPEC.md).

## Как работает

1. Telegram отправляет новые сообщения группы на HTTPS webhook Worker.
2. Worker проверяет секрет Telegram, группу и вайтлист. Сообщение сохраняется в D1, повторные обновления игнорируются.
3. Для обычного человеческого сообщения с вероятностью чата (по умолчанию **1%**) проверяется контекст: минимум три сообщения двух разных участников за последние 20 минут. При **100%** бот пытается ответить на каждое человеческое сообщение без этого минимума. Прямое упоминание `@DiscoElysiumPersBot` тоже обходит обычные условия.
4. При выполнении условий и наличии бюджета Worker атомарно резервирует лимит на вызов LLM. Для одного чата одновременно возможна только одна генерация.
5. Режиссёр на `gpt-4.1-mini` анализирует разговор и возвращает строгое решение: отвечать ли, какой голос выбрать, о чём и с каким настроением писать. При вероятности ниже 100% он может промолчать; прямое упоминание и режим 100% всегда ведут к ответу.
6. Из курируемой выборки **15 реальных игровых реплик** выбранного навыка бот подбирает **8 коротких цитат** по теме, настроению и выбранному сообщению. Второй вызов той же модели использует их как стилевые референсы и пишет новую реплику. Если результат повторяет длинный фрагмент референса, бот один раз пробует перегенерировать с другими примерами. Стоимость всех вызовов, включая частично неудачную генерацию, учитывается в D1.
7. Cron раз в 10 минут очищает устаревшие сообщения и зависшие попытки.

Для обычных ответов команд писать не нужно. Если никто не пишет или бюджет исчерпан, бот не генерирует случайную реплику. Размер контекста каждого чата настраивается командой администратора; для этого бот проверяет его статус через Telegram.

### Ответ по упоминанию

В разрешённой группе напиши `@DiscoElysiumPersBot` в сообщении: бот ответит на него независимо от вероятности 1%, числа участников и 15-минутной паузы между обычными ответами. Упоминание должно содержать точное имя бота. Лимиты расходов и защита от параллельных генераций продолжают действовать; если генерация недоступна, бот ответит коротким сообщением о проблеме. Команды и сообщения самого бота не запускают генерацию.

### Размер контекста в чате

По умолчанию бот учитывает до **30** последних сообщений за **20 минут**. Администратор группы может отправить `/context_messages 70`, чтобы установить любое целое число от **3 до 70**. Команда `/context_messages` без числа показывает текущее значение. Значение больше 70 или меньше 3 вызывает сообщение об ошибке. Настройка хранится в D1 отдельно для каждого чата; команда не попадает в контекст LLM и не запускает генерацию. Для надёжной проверки прав через `getChatMember` бот тоже должен быть администратором группы.

После push в `master` GitHub Actions применит новую миграцию и развернёт Worker.

### Вероятность в чате

Администратор разрешённой группы может отправить `/reply_percent 5`, чтобы установить **5%** вероятности запуска Режиссёра на обычное сообщение. Допустимы значения **от 0 до 100**, в том числе дробные с двумя знаками после точки, например `/reply_percent 0.5`. Команда `/reply_percent` показывает текущее значение, а `/reply_percent reset` возвращает общий дефолт `REPLY_PERCENT` (сейчас 1%). Настройка хранится в D1 отдельно для каждого чата. Команды не попадают в историю сообщений и не вызывают OpenAI; при изменении бот проверяет права через Telegram `getChatMember`.

При значении **ниже 100%** это вероятность проверить разговор Режиссёром: затем действуют условия активности беседы, 15-минутная пауза и его решение промолчать. При **100%** бот пытается ответить на каждое новое человеческое сообщение в разрешённой группе; минимум активности, пауза и право Режиссёра промолчать отключаются. Бюджет, защита от параллельных запросов и ошибки API по-прежнему могут помешать ответу. Команды и сообщения ботов игнорируются. Прямое упоминание бота обходит вероятность даже при 0%.

## CI/CD: GitHub Actions

**Ничего не нужно запускать локально, чтобы применить миграции и задеплоить бота.** Workflow [`.github/workflows/ci.yml`](.github/workflows/ci.yml) выполняется после каждого push в `master` и может запускаться вручную через GitHub Actions → **CI / Deploy** → **Run workflow**:

1. TypeScript typecheck + тесты.
2. Автоматическое применение ожидающих миграций в удалённую базу D1 `disco-elysium` (`npm run db:remote`).
3. Проверка `workers.dev`: если у аккаунта ещё нет поддомена, workflow однократно регистрирует `raphickie-apps.workers.dev` (при занятости имени — уникальный вариант). Уже существующий поддомен **не изменяется**.
4. Только при успехе всех предыдущих шагов — деплой Worker (`npm run deploy`).
5. Синхронизация OpenAI-ключа и Telegram-секретов из GitHub в Worker и регистрация webhook через Telegram Bot API.

Pull request запускает только тесты, без доступа к секретам и Cloudflare. Деплои сериализованы, чтобы избежать одновременного применения миграций. Уже применённые миграции Wrangler пропускает.

### Одноразовая настройка доступа GitHub → Cloudflare

База **`disco-elysium`** уже создана, её ID прописан в `wrangler.jsonc` с binding `DB`. Создавать базу заново не нужно.

1. В [Cloudflare Dashboard](https://dash.cloudflare.com/) найди **Account ID** твоего Cloudflare-аккаунта — это **не** Database ID D1.
2. В [Cloudflare API Tokens](https://dash.cloudflare.com/profile/api-tokens) создай токен для CI (можно использовать шаблон **Edit Cloudflare Workers**). Ограничь его нужным Cloudflare-аккаунтом и предоставь права на развёртывание Workers и **D1: Edit** для миграций. Токен не публикуй.
3. Открой [GitHub → Settings → Secrets and variables → Actions](https://github.com/raphickie/disco-elysium-bot/settings/secrets/actions) и добавь два **repository secret**:
   - `CLOUDFLARE_ACCOUNT_ID` — Account ID из Cloudflare.
   - `CLOUDFLARE_API_TOKEN` — созданный Cloudflare API token.
4. Открой [GitHub Actions](https://github.com/raphickie/disco-elysium-bot/actions) → **CI / Deploy** → **Run workflow**. После успешных тестов workflow сам применит миграцию D1 и создаст/обновит Worker.

Если один из секретов отсутствует, job **завершится ошибкой** с явным уведомлением (вместо ложного успешного деплоя). После добавления секретов достаточно повторно запустить workflow или запушить коммит.

### Секреты Telegram и OpenAI

В [GitHub Repository secrets](https://github.com/raphickie/disco-elysium-bot/settings/secrets/actions) хранятся **все три секрета приложения**:

- `TELEGRAM_BOT_TOKEN` — токен от @BotFather.
- `TELEGRAM_WEBHOOK_SECRET` — случайный секрет webhook (1–256 латинских букв, цифр, `_` или `-`).
- `OPENAI_API_KEY` — ключ OpenAI API из отдельного биллингового аккаунта OpenAI.

Уже настроенные `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` остаются там же — они служат только для деплоя.

**GitHub Actions автоматически синхронизирует все три секрета в Cloudflare Worker**, затем регистрирует webhook через Telegram `setWebhook`. Добавлять те же значения вручную через Cloudflare Dashboard **не нужно**. Если `OPENAI_API_KEY` отсутствует, деплой **не блокируется**: `/ping` работает, но генерация через OpenAI отключена. Чтобы ротировать любой ключ, обнови Repository secret и перезапусти **CI / Deploy**.

Секреты **не** передавай в чат и **не** добавляй в исходный код. Если значение секретного webhook-токена публиковалось, сгенерируй новое.
В BotFather выключи **Group Privacy** (`/setprivacy` → Disable), иначе бот не увидит обычные сообщения группы. После переключения удали его из группы и добавь заново. Предупреди участников о передаче небольших фрагментов переписки внешнему LLM-провайдеру.

### Как узнать chat ID

Для первого теста можно временно выставить `WHITELIST_ENABLED: "false"` и добавить бота в группу. Однако безопаснее узнать ID через Telegram `getUpdates` **до установки webhook** или отдельного бота: у групп ID обычно отрицательный (`-100...`). Затем внеси нужные ID через запятую в `ALLOWED_CHAT_IDS` в `wrangler.jsonc` и закоммить изменение: GitHub Actions сам задеплоит новую конфигурацию.

Вайтлист **включён**: бот обрабатывает только группы, перечисленные в `ALLOWED_CHAT_IDS`.

## Настройки в wrangler.jsonc

| Переменная | Значение в репозитории | Назначение |
| --- | --- | --- |
| `WHITELIST_ENABLED` | `true` | Обрабатывать только разрешённые чаты |
| `ALLOWED_CHAT_IDS` | `-1001890425588,-4922375667` | ID через запятую |
| `REPLY_PERCENT` | `1` | Общая вероятность по умолчанию; команда `/reply_percent` переопределяет её для чата |
| `COOLDOWN_SECONDS` | `900` | Минимальный интервал между ответами одного чата |
| `CONTEXT_WINDOW_MINUTES` | `20` | Период активной беседы |
| `CHAT_DAILY_USD` / `CHAT_MONTHLY_USD` | `0.10` / `1.00` | Бюджет одного чата |
| `GLOBAL_DAILY_USD` / `GLOBAL_MONTHLY_USD` | `1.00` / `10.00` | Общий бюджет |
| `RESERVED_USD_PER_CALL` | `0.02` | Резерв стоимости полного двухэтапного ответа |
| `OPENAI_MODEL` | `gpt-4.1-mini` | Модель Режиссёра и автора реплики |
| `OPENAI_INPUT_USD_PER_MILLION` / `OPENAI_OUTPUT_USD_PER_MILLION` | `0.40` / `1.60` | Тарифы для учёта расходов |

**Важно:** тарифы в конфигурации — лишь начальные значения, их нужно сверить с актуальной стоимостью выбранной модели. Лимиты в D1 являются внутренними ограничителями **расчётных** расходов, а не заменой платёжных лимитов OpenAI. Дополнительно установи ограничение бюджета на стороне API-провайдера. При ошибке Telegram после успешной генерации стоимость LLM всё равно учитывается. У зависших попыток резерв освобождается через 10 минут. Референсы увеличивают входной контекст второго вызова; редкая перегенерация добавляет ещё один вызов.

**Необязательно, для локальной разработки:** установи Node.js 22+, выполни `npm install`, `cp .dev.vars.example .dev.vars`, заполни локальные секреты, `npm run db:local`, `npm run dev`. Telegram webhook требует публичного HTTPS URL; обычные миграции и production deploy при этом по-прежнему выполняются автоматически из GitHub Actions.

## Проверка и диагностика

- `GET https://disco-elysium-bot.raphickie-apps.workers.dev/ping` возвращает **`pong`** даже без каких-либо Telegram/OpenAI-секретов, базы данных и доступа к Telegram. Это проверка доступности Worker, а не всей интеграции.
- Напиши боту в **личные сообщения** команду `/ping`: он ответит **`pong`** без OpenAI, D1 и настроек вероятности. Для этого по-прежнему нужны Telegram bot token и работающий webhook с его секретом.
- В **группе** бот ответит на `/ping` только при отключённом whitelist или если `chat_id` входит в `ALLOWED_CHAT_IDS`. Команды, адресованные другому боту (`/ping@OtherBot`), игнорируются. `/ping` не расходует бюджет OpenAI.
- Если запрос `/ping` из личного чата не получил ответа, проверь настройки webhook и Telegram-токена: HTTP `/ping` может при этом работать.

```bash
npm run typecheck
npm test
curl https://YOUR-WORKER.workers.dev/health
```

Для проверки генерации достаточно упомянуть `@DiscoElysiumPersBot` в разрешённой группе. Для обычных ответов требуется активный разговор минимум двух людей.

## Безопасность и ограничения

- Публичный endpoint принимает только запросы с `X-Telegram-Bot-Api-Secret-Token`.
- Чатовые сообщения обрезаются до 900 символов; сохраняются максимум на 48 часов, после чего удаляются по cron.
- Реквизиты OpenAI и Telegram хранятся только в Cloudflare Secrets.
- D1 обеспечивает атомарность бюджетных проверок, а уникальные индексы защищают от повторной обработки.
- Учет стоимости ориентировочный: возможны расхождения с фактическим биллингом OpenAI. При сбое между отправкой сообщения в Telegram и отметкой в D1 повторная отправка **не происходит автоматически**.
- Команда `/silence` и админ-панель пока не реализованы. В репозитории лежит только небольшая выборка коротких игровых реплик в [`src/voice-references.ts`](src/voice-references.ts), а не полный дамп. Обзор источников: [docs/voice-corpus-review.md](docs/voice-corpus-review.md).
