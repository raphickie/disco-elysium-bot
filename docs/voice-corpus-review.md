# Обзор локального корпуса голосов Disco Elysium

Дата анализа: 29 октября 2026. Режиссёр и второй этап генерации реализованы. Небольшая курируемая выборка коротких цитат из локального корпуса подключена к промпту; полный дамп в репозиторий не загружается.

## Где лежат данные и как их читать

Дамп найден на этой машине в `~/Downloads/de-extract` (около 542 МБ). Папки `~/Downloads/Telegram` нет. Основные файлы:

| Путь относительно `de-extract/` | Содержимое |
| --- | --- |
| `data/Disco Elysium.json` | Исходный граф: 1 501 conversation, узлы `dialogueEntries`, связи `outgoingLinks`, поля `Actor`, `Dialogue Text`, `Articy Id`. Английский текст. |
| `data/DialoguesLockitRussian.json` | Русская локализация: 73 948 терминов в `mSource.mTerms`; ключ вида `Dialogue Text/<Articy Id>`, текст в `Languages[0]`. |
| `actors.json`, `data/actors-filtered.json` | Соответствие имени и ID персонажа; во втором файле 24 навыка (ID 397–420). |
| `result/<Skill>.json` | 24 файла JSON Lines, всего 5 160 пар `request` / `response` на русском. Одна строка — один JSON-объект, номер строки ниже считается с 1. |
| `result2/<Skill>.json` | JSON Lines с одним `response`; менее полезен для отбора, потому что потерян входящий контекст. |
| `conversations-rus.json`, `conversations-rus2.json` | Производные английско-русские записи (`id` здесь — ID актёра, **не** ID диалога). Не использовать как первичный адрес записи. |

Для каждой выбранной ниже строки ответ сопоставлен с локализацией по `Articy Id`, актёр проверен по исходному графу, а `request` проверен как текст входящего узла. Совпадения подтверждены для всех приведённых записей. Несколько реплик дублируются в графе: для них указан один конкретный узел. Извлечение `result/` покрывает только часть реплик навыков; число строк не следует считать полным объёмом голоса. Полные игровые тексты и дамп в репозиторий не добавлять.

Обозначения в таблице: `стр.` — номер строки в `result/<Skill>.json`; `узел` — `conversationID/dialogueEntryID` внутри `data/Disco Elysium.json`; `Articy` — точный идентификатор локализации. Все файлы корпуса остаются локальными в `~/Downloads/de-extract/`.

## Как применять в двухэтапном пайплайне

1. Проверять вероятность чата **до** LLM-вызовов: по умолчанию 1%, администратор может изменить её командой `/reply_percent <0–100>`. После срабатывания собрать до установленного для чата числа последних сообщений с авторами и хронологией. По умолчанию это 30; администратор может изменить значение командой `/context_messages <3–70>`. Для коротких сообщений стоимость почти не ограничивает выбор: дополнительные 30 сообщений при переходе с 30 на 60, по 25–40 входных токенов (включая имя автора и форматирование), стоят примерно $0.00030–0.00048 за один вызов `gpt-4.1-mini` при $0.40 за миллион входных токенов; если весь контекст отправлять обоим этапам, примерно вдвое больше. Это оценка, а не измерение реального чата. Ограничение 20 минут может дать меньше установленного числа сообщений.
2. «Режиссёр» получает контекст и закрытый список голосов. Сейчас он возвращает структурированный результат: `respond`, `voice`, `focus_message` (порядковый номер сообщения в контексте), `topic`, `mood`, `angle`. Для обычной беседы возможен `respond=false`; прямое упоминание принудительно ведёт ко второму этапу.
3. В `src/voice-references.ts` сохранены по 15 коротких цитат для каждого из 10 активных голосов: текст, номер строки исходного `result/<Skill>.json` и тематические теги. Для конкретной реплики `src/references.ts` выбирает 8 примеров по совпадениям тегов и слов с темой, настроением, углом Режиссёра и сообщением в фокусе. Полный дамп остаётся только локально.
4. Второй вызов получает те же сообщения, выбранный голос, тему, настроение, угол наблюдения и 8 цитат как стилевые референсы. Инструкция: написать **новую**, короткую, контекстную реплику по-русски; не продолжать игровой сюжет и не воспроизводить эталон.
5. Перед отправкой проверяется совпадение последовательности слов с референсами. При длинном совпадении бот один раз перегенерирует реплику с другими примерами. Для дальнейшей оценки качества полезно вручную сравнить разные голоса на одних и тех же реальных, обезличенных контекстах чата.

Текущая выборка — ручная и небольшая; она не охватывает все игровые ситуации. Для следующей итерации можно хранить более широкий корпус приватно, добавить контекст исходного диалога и проверять близость ко всему корпусу, а не только к восьми примерам текущего ответа.
