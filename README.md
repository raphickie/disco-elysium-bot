# Disco Elysium Telegram Bot 🧠🎲

Небольшой **Telegram-бот на TypeScript + Cloudflare Workers + D1**. Примерно в 1% подходящих сообщений (вероятность настраивается) отвечает короткой нелепой/умной/мрачной репликой одного из «внутренних голосов» Disco Elysium. Реплика учитывает настоящую недавнюю переписку, а не является случайной цитатой.

Основные требования — [SPEC.md](SPEC.md). Подборки оригинальных примеров — [VOICE-SAMPLES.md](VOICE-SAMPLES.md).

## Возможности

- **Telegram webhook**: Worker просыпается только по запросу Telegram, отдельный сервер не нужен.
- **Вайтлист** с флагом `WHITELIST_ENABLED`, безопасно включённым по умолчанию (пустой список означает *все группы запрещены*).
- **Вероятность `REPLY_PERCENT`** (по умолчанию 1%), отдельные настройки для чатов через D1.
- **Контекст**: последние 10 текстовых сообщений за 30 минут; минимум четыре сообщения от двух разных людей.
- **Rate limit**: cooldown, максимум ответов за сутки, денежные ограничения *за день и месяц* одновременно на каждый чат и на всё приложение.
- **Денежная защита**: перед платным API-запросом одним SQL-запросом резервируется завышенная оценка стоимости. После ответа сумма уточняется по `usage`; если ответ не пришёл, резерв остаётся учтённым. Даже два параллельных срабатывания не должны превысить выставленные лимиты. **Это оценка расходов на модель, а не финансовый лимит самой OpenAI Platform** — для второго уровня защиты поставь лимит/уведомление на стороне OpenAI.
- **Безопасность**: проверка webhook-secret, игнор ботов и служебных сообщений, `UNIQUE(chat_id, message_id)` от повторных webhook, OpenAI и Telegram токены только в секретах Worker.
- **Приватность**: последние сообщения хранятся в D1 не более 24 часов, после чего удаляются Cron-задачей каждые 6 часов (значит фактическое удаление может занять до ~30 часов). Сообщения отправляются в OpenAI **только при попытке генерации**, а не на каждом сообщении. Журнал расходов хранится до 65 дней и не содержит содержимого сообщений.

## Быстрый запуск

Тебе понадобятся **Node.js 22+**, Telegram-бот от [@BotFather](https://t.me/BotFather), Cloudflare-аккаунт (Workers + D1), а также **отдельный OpenAI API-ключ с настроенной оплатой**. Подписка ChatGPT не оплачивает запросы API.

### 1. Telegram: создай бота

1. Отправь `@BotFather` команду `/newbot`, сохрани токен **вне GitHub**.
2. Через `/setprivacy` выбери своего бота и **Disable**, иначе он не будет видеть обычную переписку в группе. Если бот уже добавлен в группу, удали и добавь заново после изменения настройки.
3. Добавь бота в тестовую группу. Для отправки сообщений нужны соответствующие права чата.

### 2. Cloudflare: установи зависимости и опубликуй Worker

```bash
npm install
npx wrangler login
npm run deploy
npm run db:migrate:remote
```

`wrangler.jsonc` содержит D1 binding `DB` без жёстко прописанного ID: **современный Wrangler автоматически создаёт/привязывает базу при первом `deploy`**. После этого миграция создаст таблицы. Если твой Wrangler попросит ID вручную, создай базу через `npx wrangler d1 create disco-elysium-bot-db --binding DB --update-config`, затем повтори деплой и миграции.

Проверь, что по `https://<your-worker>.workers.dev/health` возвращается `ok`.

### 3. Добавь три секрета

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
npx wrangler secret put OPENAI_API_KEY
```

Для `TELEGRAM_WEBHOOK_SECRET` используй случайную строку из букв/цифр/`-`/`_`, например результат `openssl rand -hex 24`. Один и тот же секрет нужно задать и Worker, и Telegram webhook. Не записывай реальные секреты в `wrangler.jsonc`, `.env` или сообщения Telegram.

### 4. Зарегистрируй webhook Telegram

Укажи публичный URL Worker, **тот же** Telegram-токен и webhook-секрет, которые ты только что сохранил в Worker. В Bash/Zsh можно ввести секреты без отображения на экране:

```bash
export WORKER_URL="https://<your-worker>.workers.dev"
read -rs -p 'Telegram token: ' TELEGRAM_BOT_TOKEN; echo
read -rs -p 'Webhook secret: ' TELEGRAM_WEBHOOK_SECRET; echo
export TELEGRAM_BOT_TOKEN TELEGRAM_WEBHOOK_SECRET
npm run webhook:set
unset TELEGRAM_BOT_TOKEN TELEGRAM_WEBHOOK_SECRET
```

Скрипт `scripts/set-webhook.mjs` вызывает Telegram `setWebhook` на `/telegram/webhook`, передаёт заголовочный секрет, выбирает только события `message` и устанавливает `max_connections=1` для небольшой нагрузки группы. Проверь результат в Bot API `getWebhookInfo`, если сообщения не приходят.

### 5. Узнай ID группы и разреши её

Вайтлист **включён** и по умолчанию **пустой**, поэтому бот пока молчит. Для получения ID открой отдельный терминал:

```bash
npx wrangler tail
```

Отправь тестовое текстовое сообщение в свою Telegram-группу. В логах будет событие `chat_not_whitelisted` с `chatId` (например, `-1001234567890`). Содержимое сообщений не логируется.

В файле `wrangler.jsonc` пропиши:

```json
"WHITELIST_ENABLED": "true",
"ALLOWED_CHAT_IDS": "-1001234567890,-1009876543210",
"REPLY_PERCENT": "1"
```

Затем `npm run deploy`. Для тестирования можно временно поставить `REPLY_PERCENT=100` и `MIN_CONTEXT_MESSAGES=2`, после теста вернуть 1%. При `WHITELIST_ENABLED=false` Worker принимает **все группы**, куда добавлен бот — проверяй глобальные лимиты бюджета!

### 6. Настрой вероятность и ограничения

Все настройки — в `wrangler.jsonc` в блоке `vars`. Основные значения:

| Переменная | По умолчанию | Значение |
|---|---:|---|
| `REPLY_PERCENT` | `1` | Вероятность срабатывания на сообщение, % (0–100) |
| `MIN_CONTEXT_MESSAGES` | `4` | Минимум сообщений недавней беседы |
| `MIN_CONTEXT_USERS` | `2` | Минимум разных отправителей |
| `COOLDOWN_SECONDS` | `1200` | Минимальный промежуток между попытками ответа в одном чате |
| `MAX_DAILY_REPLIES_PER_CHAT` | `8` | Максимальное число генераций на чат за сутки (UTC) |
| `CHAT_DAILY_LIMIT_USD` | `0.05` | Предел на модель на один чат в сутки |
| `CHAT_MONTHLY_LIMIT_USD` | `0.50` | Предел на модель на один чат в месяц |
| `GLOBAL_DAILY_LIMIT_USD` | `0.50` | Предел всех чатов за сутки |
| `GLOBAL_MONTHLY_LIMIT_USD` | `5` | Предел всех чатов за месяц |
| `MAX_OUTPUT_TOKENS` | `220` | Ограничение токенов ответа, включая невидимые |
| `OPENAI_MODEL` | `gpt-6-luna` | Модель OpenAI Responses API |
| `BOT_ENABLED` | `true` | Общий выключатель бота |
| `MESSAGE_TTL_HOURS` | `24` | TTL сообщений до удаления Cron |

**Денежные расчёты:** по состоянию на октябрь 2026 г. для `gpt-6-luna` выставлены стандартные тарифы $0.10/млн входных токенов и $0.50/млн выходных. При выборе другой модели **обязательно** укажи корректные `MODEL_INPUT_USD_PER_MILLION` и `MODEL_OUTPUT_USD_PER_MILLION`. Если модель или тариф изменились, обнови цены. Приложение использует оценку и фактическую статистику токенов, а не информацию о списаниях из API-биллинга.

### Необязательные настройки конкретного чата

Для группы можно переопределить частоту и лимиты, не затрагивая другие чаты:

```bash
npx wrangler d1 execute DB --remote --command \
  "INSERT INTO chat_settings (chat_id, enabled, reply_percent, chat_daily_limit_usd, cooldown_seconds) VALUES ('-1001234567890', 1, 2.5, 0.02, 900) ON CONFLICT(chat_id) DO UPDATE SET enabled=excluded.enabled, reply_percent=excluded.reply_percent, chat_daily_limit_usd=excluded.chat_daily_limit_usd, cooldown_seconds=excluded.cooldown_seconds, updated_at=unixepoch();"
```

Для выключения бота в конкретной группе — `UPDATE chat_settings SET enabled=0 WHERE chat_id='-100...';`. Чтобы убрать индивидуальную вероятность, выставь `reply_percent=NULL`. Условие общего вайтлиста сохраняется даже при `enabled=1` для отдельного чата.

## Как бот решает, когда отвечать

1. Telegram присылает подписанный webhook; Worker проверяет заголовок и допускает только сообщения людей в разрешённых группах.
2. Сообщение кратко сохраняется в D1. Дубликаты не считаются повторно. Для **каждого нового сообщения** разыгрывается вероятность `REPLY_PERCENT`.
3. При выигрыше бот смотрит недавний разговор; если недостаточно сообщений/участников, **молчит** без API-запроса.
4. По бюджету, числу реплик в сутки и cooldown выполняется **одна атомарная SQL-попытка резервирования**. Если ограничения нарушены — бот молчит.
5. Генерируется комментарий одним голосом. Запрос в OpenAI сделан с `store:false`, на него накладывается лимит токенов и таймаут.
6. Worker отправляет текст через Telegram API; при ошибке пишет только код проблемы, **без текста разговора и секретов**.

## Примеры сообщений

**ВНУТРЕННЯЯ ИМПЕРИЯ — [Критический провал]**

> Ты хотел общения. Близости. Человеческого тепла. Но теперь у тебя есть бот, который пишет за тебя, когда вы слишком долго обсуждаете доставку еды.

**ТРЕПЕТ — [Провал]**

> Город засыпает. Последняя электричка увозит последних пассажиров. В это время несколько взрослых людей пытаются выбрать, где заказать пиццу. История не запомнит победителя.

Это **оригинальные примеры**, а не дословные цитаты из игры. Реплики не обязаны быть депрессивными: набор голосов и характеров редактируется в `src/prompt.ts`.

## Локальная разработка и тесты

```bash
npm install
npm run db:migrate:local
cp .dev.vars.example .dev.vars   # только для локального Worker
npm run dev
npm test
npm run typecheck
npm run check:worker
```

Тесты не звонят в Telegram/OpenAI: используют заглушки HTTP и SQLite для проверки тех же SQL-ограничений, что применяются в D1. CI запускается через GitHub Actions, но **не деплоит Worker без явной настройки**.

## Надёжность и ограничения

- Доставка ответа — **best effort**: при перезапуске Worker после подтверждения webhook редкая генерация может пропасть. Telegram сам повторяет недоставленные webhook, а новые сообщения дедуплицируются по `(chat_id,message_id)`. Редкие сетевые таймауты отправки не позволяют гарантировать абсолютное «ровно один ответ» без более сложной очереди/идемпотентности Telegram API.
- Физический лимит биллинга определяется провайдером. SQL-резервирование ограничивает прогнозируемые расходы **на модель**, но не предотвращает изменение внешних тарифов, скрытые доплаты или нагрузку вне этого Worker. Поставь отдельный бюджет на OpenAI Platform.
- `ctx.waitUntil` даёт ограниченное время на сетевые вызовы. Таймауты OpenAI/Telegram поставлены с запасом; при массовой нагрузке стоит переходить на Cloudflare Queues.
- Бот может отвечать только там, где у него есть права отправлять сообщения. Для обычной переписки в группе у него должна быть выключена privacy mode.
- **Сообщи участникам группы**, что бот собирает последние сообщения и иногда отправляет небольшой фрагмент в OpenAI для генерации. Не сохраняй разговоры дольше необходимого.
