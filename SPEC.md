# Disco Elysium Bot — техническое задание

1. **Платформа.** Telegram-бот для групп и супергрупп на **TypeScript + Cloudflare Workers** (webhook); последние сообщения, настройки чатов и счётчики хранить в **Cloudflare D1**. Без постоянно запущенного сервера.
2. **Допуск чатов.** Настройка `WHITELIST_ENABLED` и список разрешённых `chat_id`: при `true` бот обрабатывает только чаты из списка, при `false` — любой чат, куда его добавили. По умолчанию — включённый вайтлист.
3. **Когда отвечать.** Для каждого подходящего сообщения проверять настраиваемую вероятность `REPLY_PERCENT` (например, **1%**); не вызывать LLM, если проверка не пройдена. Учитывать только человеческие сообщения в активном разговоре, игнорировать свои сообщения, сервисные события и повторы Telegram.
4. **Контекст.** Перед ответом брать ограниченное число последних сообщений чата вместе с авторами и временем, чтобы реагировать на реальную тему беседы, а не выдавать случайную цитату. Историю хранить недолго, с настраиваемым сроком удаления.
5. **Характер реплик.** Генерировать короткие оригинальные комментарии голосами навыков **Disco Elysium** (Внутренняя империя, Трепет, Электрохимия, Логика, Эмпатия, Авторитет и др.), с указанием навыка и при желании результата проверки: «Успех», «Провал», «Критический провал». Тон может быть добрым, смешным, философским, жёстким и иногда матерным — по контексту; возможные цитаты из игры использовать только как краткие референсы.
6. **Контроль расходов и спама.** Настраиваемый **лимит стоимости LLM по каждому чату** (за сутки/месяц), общий лимит, cooldown между ответами и ограничение частоты запросов; при исчерпании лимита бот молчит. Учитывать фактические токены/стоимость и защищаться от параллельных двойных ответов.
7. **Управление и безопасность.** Настройки вероятности, вайтлиста, лимитов и стиля задаются конфигурацией, без правок основной логики. Telegram- и OpenAI-токены — только в секретах Cloudflare; webhook проверять по секрету. Предусмотреть минимальные логи, обработку ошибок и инструкцию по развёртыванию; предупредить участников, что фрагменты переписки могут отправляться LLM-провайдеру.

**Назначение документа:** опорное ТЗ для реализации и последующих изменений; детали конфигурации и технические решения можно уточнять, сохраняя перечисленное поведение.
