# Disco Elysium Bot — техническое задание

1. **Платформа.** Telegram-бот для групп и супергрупп на **TypeScript + Cloudflare Workers** (webhook); последние сообщения, настройки чатов и счётчики хранить в **Cloudflare D1**. Без постоянно запущенного сервера.
2. **Допуск чатов.** Настройка `WHITELIST_ENABLED` и список разрешённых `chat_id`: при `true` бот обрабатывает только группы из списка, при `false` — любую группу, куда его добавили. По умолчанию — включённый вайтлист. Генерацию в ЛС разрешать только пользователям из отдельного `ALLOWED_PRIVATE_USER_IDS` (сейчас `80126579`), независимо от группового вайтлиста; по умолчанию список пуст. Проверять ID отправителя и личного чата до записи истории и генерации.
3. **Когда отвечать.** Для обычного подходящего сообщения проверять вероятность, заданную для чата командой администратора `/reply_percent <0–100>`; при отсутствии настройки брать общий дефолт `REPLY_PERCENT` (например, **1%**). Команда без аргумента показывает значение, `reset` удаляет переопределение. Не вызывать LLM, если проверка не пройдена. При значении 100% каждое человеческое сообщение запускает обязательный ответ без минимума активности и cooldown; лимиты расходов и защита от параллельной генерации остаются. Прямое упоминание `@DiscoElysiumPersBot` в разрешённой группе вызывает ответ независимо от вероятности, активности разговора и cooldown. Игнорировать свои сообщения, сервисные события и повторы Telegram.
   **ЛС:** обычное сообщение разрешённого пользователя требует ответа через Режиссёра и Писателя без вероятности, минимума активности и cooldown. История и бюджет учитываются по ID личного чата; ограничения расходов, защита от дублей и параллельных генераций действуют. Команды настроек остаются групповыми.
   **Прямой выбор голоса:** все 24 голоса доступны через отдельные команды из списка в README, например `/shivers` (Трепет), `/electrochemistry` (Электрохимия) и `/halflight` (Сумрак). В разрешённой группе или разрешённом личном чате они вызывают сразу Писателя с выбранным голосом, без Режиссёра, случайного выбора, вероятности, минимума активности и cooldown. Учитывать текст после команды и сообщение, выбранное через Reply, в пределах лимита контекста; пустая история допускает вступительную реплику. Сами команды не сохранять в истории. Сохранить лимиты расходов, защиту от параллельных и повторных генераций; об отказе по лимиту или ошибке уведомлять пользователя.
4. **Контекст.** Перед ответом брать ограниченное число последних сообщений чата вместе с авторами и временем, чтобы реагировать на реальную тему беседы, а не выдавать случайную цитату. Историю хранить недолго, с настраиваемым сроком удаления.
5. **Характер реплик.** Генерировать короткие оригинальные комментарии голосами навыков **Disco Elysium** (Внутренняя империя, Трепет, Электрохимия, Логика, Эмпатия, Авторитет и др.), с указанием навыка и при желании результата проверки: «Успех», «Провал», «Критический провал». Тон может быть добрым, смешным, философским, жёстким и иногда матерным — по контексту; возможные цитаты из игры использовать только как краткие референсы.
   **Режиссёр:** первый вызов LLM возвращает структурированное решение о том, отвечать ли, каким голосом, по какой теме и с каким углом наблюдения. Для обычной беседы при вероятности ниже 100% он может выбрать молчание; прямое упоминание и режим 100% требуют ответа. Перед вторым вызовом писатель получает до 15 коротких цитат выбранного навыка как стилевые референсы; все 24 навыка доступны Режиссёру, а тройка кандидатов выбирается по весам. Второй вызов пишет новую реплику выбранным голосом; при дословном совпадении с референсом допускается одна перегенерация. Расходы всех вызовов учитываются вместе.
6. **Контроль расходов и спама.** Настраиваемый **лимит стоимости LLM по каждому чату** (за сутки/месяц), общий лимит, cooldown между обычными ответами при вероятности ниже 100% и ограничение частоты запросов. При исчерпании лимита обычный ответ пропускается, а на прямое упоминание отправляется короткое уведомление. Учитывать фактические токены/стоимость и защищаться от параллельных двойных ответов.
7. **Управление и безопасность.** Вероятность задаётся командой администратора отдельно для каждого чата и хранится в D1; конфигурация содержит дефолт. Вайтлист, лимиты и стиль задаются конфигурацией, без правок основной логики. Telegram- и OpenAI-токены — только в секретах Cloudflare; webhook проверять по секрету. Предусмотреть минимальные логи, обработку ошибок и инструкцию по развёртыванию; предупредить участников, что фрагменты переписки могут отправляться LLM-провайдеру. **Проверка работоспособности:** публичный HTTP `GET /ping` → `pong` без любых секретов; команда Telegram `/ping` → `pong` без обращения к D1/OpenAI, в личном чате или разрешённой группе (для Telegram-ответа необходимы Telegram Bot Token и webhook).

**Назначение документа:** опорное ТЗ для реализации и последующих изменений; детали конфигурации и технические решения можно уточнять, сохраняя перечисленное поведение.
